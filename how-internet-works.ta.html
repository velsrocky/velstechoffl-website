இணையம் உண்மையில் எவ்வாறு வேலை செய்கிறது?

Basics DNS Aug 24, 2026 · 7 நிமிட வாசிப்பு

இணையம் மந்திரம் போல் உணர்கிறது, ஆனால் அது உண்மையில் ஒன்றன் மேல் ஒன்றாக அடுக்கப்பட்ட மூன்று கருத்துக்கள் மட்டுமே: முகவரியிடல், பெயரிடல், மற்றும் அனுப்புதல். அவற்றைப் புரிந்துகொண்டால், முழு விஷயமும் அர்த்தமுள்ளதாகிறது.

அஞ்சல் ஒப்புமை

இணையத்தில் தரவை அனுப்புவது ஒரு கடிதத்தை அஞ்சலில் அனுப்புவது போன்றது:

  • IP முகவரி = தெரு முகவரி. இது நெட்வொர்க்கில் ஒரு கணினியை தனித்துவமாக அடையாளம் காட்டுகிறது.
  • பாக்கெட் = கடிதம், ஒரு தரவுத் துண்டு மற்றும் இலக்கு முகவரியைச் சுமந்து செல்கிறது.
  • ரூட்டர்கள் = அஞ்சல் அலுவலகங்கள், ஒவ்வொரு பாக்கெட்டையும் அதன் இலக்கை நோக்கி அனுப்புகின்றன.
  • DNS = தொலைபேசி புத்தகம், "velstech.net" போன்ற பெயர்களை IP முகவரிகளாக மொழிபெயர்க்கிறது.

நெட்வொர்க்கிங்கின் 90% அதுதான். ஒவ்வொரு பகுதியையும் பார்க்கலாம்.

1. IP முகவரிகள்: முகவரியிடல்

இணையத்தில் ஒவ்வொரு சாதனத்திற்கும் ஒரு தனிப்பட்ட எண் உள்ளது – ஒரு IP முகவரி. பயன்பாட்டில் இரண்டு பதிப்புகள் உள்ளன:

  • IPv4 – 185.199.108.153 போன்றது. நான்கு எண்கள், ~4.3 பில்லியன் மொத்தம். நாங்கள் தீர்ந்துவிட்டோம்.
  • IPv6 – 2606:4700:4700::1111 போன்றது. மிக அதிகமான முகவரிகள், மெதுவாக வெளியிடப்படுகிறது.

பெரும்பாலான மக்கள் இவற்றை ஒருபோதும் பார்ப்பதில்லை, ஏனெனில் NAT – உங்கள் வீட்டு ரூட்டர் ஒவ்வொரு சாதனத்திற்கும் ஒரு தனிப்பட்ட முகவரியை (எ.கா. 192.168.1.5) அளித்து, வெளி உலகத்துடன் ஒரு பொது முகவரியை பகிர்ந்து கொள்கிறது. உங்கள் எல்லா சாதனங்களும் ஒரே PO பெட்டி வழியாக "அஞ்சல்" செய்கின்றன.

2. DNS: தொலைபேசி புத்தகம்

யாரும் ஒரு உலாவியில் 185.199.108.153 ஐ தட்டச்சு செய்ய விரும்பவில்லை. அதற்கு பதிலாக நாங்கள் velstech.net ஐ தட்டச்சு செய்கிறோம், மேலும் டொமைன் பெயர் அமைப்பு எங்களுக்காக பொருந்தக்கூடிய IP முகவரியை தேடுகிறது.

நீங்கள் ஒரு டொமைனை தட்டச்சு செய்யும்போது, இது மில்லி விநாடிகளில் நடக்கிறது:

  1. உங்கள் கணினி அதன் கட்டமைக்கப்பட்ட DNS சர்வரை (பொதுவாக உங்கள் ரூட்டர் அல்லது ISP) கேட்கிறது.
  2. பதில் கேச் செய்யப்படவில்லை என்றால், சர்வர் ஒரு சங்கிலியைப் பின்தொடர்கிறது: ரூட் சர்வர்கள் → .net சர்வர்கள் → velstech.net-க்கான குறிப்பிட்ட நேம்சர்வர்.
  3. இறுதி நேம்சர்வர் IP முகவரியை திருப்பி அளிக்கிறது, இது கேச் செய்யப்படுகிறது, எனவே அடுத்த முறை உடனடியாக இருக்கும்.

DNS பதிவுகளில் வகைகள் உள்ளன: A ஒரு டொமைனை IPv4 முகவரிக்கு சுட்டிக்காட்டுகிறது, CNAME ஒரு டொமைனை மற்றொன்றுக்கு சுட்டிக்காட்டுகிறது, MX மின்னஞ்சலை கையாளுகிறது. அதனால்தான் "ஒரு டொமைனை வாங்குவது" உண்மையில் "DNS தொலைபேசி புத்தகத்தில் உள்ளீட்டை சொந்தமாக்குவது" என்பதாகும்.

3. பாக்கெட்டுகள் மற்றும் ரூட்டிங்: அனுப்புதல்

உங்கள் தரவு ஒரே துண்டாக பயணிப்பதில்லை. அது சிறிய பாக்கெட்டுகளாக வெட்டப்படுகிறது, ஒவ்வொன்றும் மூல மற்றும் இலக்கு முகவரிகளுடன் முத்திரையிடப்பட்டு, பின்னர் அனுப்பப்படுகிறது.

ஒவ்வொரு பாக்கெட்டும் தனித்தனியாக ரூட்டர்கள் வழியாக நகர்கிறது – இலக்கைப் படித்து பாக்கெட்டை சரியான "அடுத்த ஹாப்" நோக்கி அனுப்பும் சாதனங்கள். வழித்தடங்கள் நேரடியாக மாறலாம்: ஒரு பாதை நெரிசலாக இருந்தால் அல்லது செயலிழந்தால், பாக்கெட்டுகள் வேறு வழியை எடுக்கின்றன.

ஆயிரக்கணக்கான பக்கங்களை ஒவ்வொரு பக்கத்தையும் தனித்தனியாக அஞ்சலில் அனுப்புவதன் மூலம் ஒரு நண்பருக்கு வழங்குவது போல நினைத்துப் பாருங்கள். அவை ஒழுங்கற்ற முறையில் மற்றும் வெவ்வேறு அஞ்சல் அலுவலகங்கள் வழியாக வருகின்றன, ஆனால் உங்கள் நண்பர் (பெறும் மென்பொருள்) அவற்றை சரியான வரிசையில் மீண்டும் இணைக்கிறார்.

அதை நம்பகமாக்கும் புரோட்டோகால்கள்

அந்த மூல அனுப்புதலின் மேல் இரண்டு புரோட்டோகால்கள் கனமான வேலையைச் செய்கின்றன:

  • TCP (டிரான்ஸ்மிஷன் கண்ட்ரோல் புரோட்டோகால்) – விநியோகத்தை உறுதி செய்கிறது. இது பாக்கெட்டுகளுக்கு எண்கள் இடுகிறது, இழப்பைக் கண்டறிந்து, காணாமல் போனதை மீண்டும் அனுப்புகிறது. வலை, மின்னஞ்சல், கோப்பு பரிமாற்றங்களுக்கு பயன்படுத்தப்படுகிறது. நம்பகமானது ஆனால் கனமானது.
  • UDP (யூசர் டேட்டாகிராம் புரோட்டோகால்) – எந்த உத்தரவாதமும் இல்லை, வெறும் வேகம். சுடு மற்றும் மறந்துவிடு. வீடியோ அழைப்புகள், கேம்கள், DNS-க்கு பயன்படுத்தப்படுகிறது. தாமதமான பிரேமை விட கைவிடப்பட்ட பிரேம் சிறப்பாக இருக்கும்போது சரியானது.

அனைத்தையும் இணைத்தல்: velstech.net ஐ ஏற்றுதல்

  1. நீங்கள் velstech.net ஐ தட்டச்சு செய்து Enter அழுத்துகிறீர்கள்.
  2. DNS அதை 185.199.108.153 ஆக தீர்க்கிறது (மில்லி விநாடிகளில், கேச் வழியாக).
  3. உங்கள் உலாவி TCP பாக்கெட்டுகளாக பிரிக்கப்பட்ட ஒரு கோரிக்கையை அனுப்புகிறது, அந்த IP-க்கு முகவரியிடப்பட்டது.
  4. இணையம் முழுவதும் உள்ள ரூட்டர்கள் ஒவ்வொரு பாக்கெட்டையும் GitHub சர்வர்களை நோக்கி அனுப்புகின்றன.
  5. சர்வர் பதிலளிக்கிறது – அதன் கோப்புகள் பாக்கெட்டுகளாக பிரிக்கப்பட்டு அதே வழியில் திருப்பி அனுப்பப்படுகின்றன.
  6. உங்கள் உலாவி பாக்கெட்டுகளை மீண்டும் இணைத்து பக்கத்தை வழங்குகிறது.

மொத்த சுற்றுப்பயணம்: பெரும்பாலும் நூறு மில்லி விநாடிகளுக்கு குறைவு. நூற்றுக்கணக்கான ரூட்டர்கள், ஆயிரக்கணக்கான பாக்கெட்டுகள், மற்றும் ஒரு தொலைபேசி புத்தக தேடல் – நீங்கள் கண் சிமிட்டி முடிப்பதற்கு முன்பே.

உங்களுக்கு ஏன் முக்கியம்

ஒரு டொமைனை வாங்கும் தருணத்தில், ஒரு வீட்டு சர்வரை இயக்கும்போது, அல்லது "இணையம் ஏன் மெதுவாக உள்ளது" என்பதை பிழைத்திருத்தும்போது நெட்வொர்க்கிங் அறிவு சுருக்கமாக இருப்பதை நிறுத்துகிறது. இந்த மூன்று கருத்துக்கள் – IP முகவரிகள், DNS, மற்றும் பாக்கெட் ரூட்டிங் – நீங்கள் எப்போதாவது அமைக்கும் ஒவ்வொரு இணைக்கப்பட்ட விஷயத்திற்கும் அடித்தளமாகும்.
