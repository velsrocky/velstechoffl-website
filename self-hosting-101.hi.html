Self-hosting 101: घर पर क्या चला सकते हैं?

Networking Self-hosting Projects Aug 24, 2026 · 7 मिनट का पठन 🤖 AI-assisted

Self-hosting का मतलब है अपनी services को किसी और के cloud को पैसे देने के बजाय अपने hardware पर खुद चलाना। यह private है, सीखने का बेहतरीन तरीका है, और कई चीज़ों के लिए लगभग मुफ़्त है। यहाँ बताया गया है कि घर पर क्या host करना worth है – और क्या नहीं।

शुरू करने के लिए क्या चाहिए

Entry point बहुत छोटा है:

  • Raspberry Pi 4/5 – classic। ~$50–80, कुछ watts power लेता है।
  • पुराना laptop या desktop – बिल्कुल ठीक, और आपके पास शायद पहले से है।
  • Mini PC (N100-class) – सस्ता, शांत, low-power, आश्चर्यजनक रूप से capable।
  • Storage – अच्छी external या internal drive, ideally आपका boot drive नहीं।

Linux install करें (OS section देखें), मशीन को static IP दें, और आप तैयार हैं। Docker अगला हिस्सा नाटकीय रूप से आसान बना देता है – ज़्यादातर self-hosted apps one-command installs हैं।

आसान, high-value जीत

ये वे projects हैं जिनसे लोग आमतौर पर शुरू करते हैं:

  • Media server – Jellyfin या Plex। अपनी movies और music को किसी भी device पर stream करें। Jellyfin मुफ़्त और पूरी तरह self-contained है। यही #1 वजह है जिससे लोग self-hosting शुरू करते हैं।
  • Personal cloud – Nextcloud। आपका खुद का Dropbox/Google Drive। Files, photos, notes, contacts – फ़ोन से accessible। "किसी अजनबी के server पर sync" को "मेरी closet में sync" से बदलें।
  • Network level पर ad-blocking – AdGuard Home या Pi-hole। हर device के लिए ads और trackers को network से ही block करें, router level पर, load होने से पहले।
  • Home dashboard – Home Assistant। Smart devices, sensors और automations को एक private dashboard में जोड़ें। Full smart-home ownership का gateway drug।

एक कदम आगे

एक बार comfortable हो जाएँ, तो और जोड़ें:

  • Password manager – Vaultwarden। आपके passwords, self-hosted (Bitwarden के server का drop-in replacement)।
  • Backup target। अपने computers का backup रात में home server पर करें। Server का खुद off-site backup होता है।
  • Notes और docs – Obsidian sync, Bookstack या Trilium। आपका खुद का knowledge base।
  • Personal blog या site। खुद host करें – हालाँकि GitHub Pages पर static site अक्सर ज़्यादा समझदारी है।
  • Git server – Gitea। Personal projects के लिए आपका खुद का GitHub।

इसे internet पर expose करना

घर के अंदर services local network पर बस काम करती हैं। जैसे ही आप बाहर से access चाहते हैं, आपके पास विकल्प हैं – बढ़ती मेहनत के क्रम में:

  1. VPN – Tailscale या WireGuard। सुरक्षित, modern choice। आप एक private network join करते हैं जो कहीं से भी आपके home server तक पहुँचता है। कोई ports open नहीं, कोई exposure नहीं। हर चीज़ के लिए recommended।
  2. Cloudflare Tunnel। एक free tunnel जो बिना कोई port खोले आपके server को Cloudflare से जोड़ता है। Specific apps को publicly share करने के लिए शानदार।
  3. Port forwarding + DDNS। पुराना तरीका: port खोलें, बदलते IP के लिए DDNS इस्तेमाल करें। काम करता है, लेकिन server को सीधे expose करता है – सिर्फ मज़बूत security के साथ ही करें।
Rule of thumb: private access के लिए VPN (Tailscale) इस्तेमाल करें, और Cloudflare Tunnel तब जब आप कुछ public करना चाहते हैं। Open internet पर raw port forwarding से बचें जब तक आप अपने setup को लेकर confident न हों।

क्या self-host नहीं करना चाहिए

Honesty corner। कुछ चीज़ें worth नहीं हैं:

  • Business-critical email – घर के IP से email reliably deliver करना nightmare है (spam filters residential IPs से नफ़रत करते हैं)। Mail provider इस्तेमाल करें।
  • कुछ भी जो 24/7 enterprise uptime माँगे – घर का internet और power data centers नहीं हैं।
  • Backups जिन्हें आप खोना afford नहीं कर सकते – हमेशा off-site copy रखें (3-2-1 rule)।
  • जो आप maintain नहीं करेंगे – हर self-hosted service को updates चाहिए। Unmaintained = unpatched = risk।

Starter checklist

1. Get hardware (Pi / old laptop / mini PC)
2. Install Linux + Docker
3. Give it a static local IP
4. Start with ONE service (Jellyfin is the classic)
5. Add Tailscale for secure remote access
6. Set up nightly backups to an external drive
7. Repeat updates regularly (and actually do them)

Self-hosting एक hobby है जो learning और privacy में खुद का पैसा वसूल कर देता है। एक चीज़ से शुरू करें, एक weekend में दस services install करने से बचें, और सब कुछ updated रखें। छह महीने बाद आपके पास एक छोटा private cloud होगा जो पूरी तरह आपका है।
